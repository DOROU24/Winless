# Демо-данные

Файлы создаёт `scripts/generate_demo.py`. Каждый файл — **полный снимок** состояния (как настоящая выгрузка из ITSM),
а не «патч»: так сравнение снимков работает честно.

Все даты посчитаны от «демо-сейчас» **21.11.2026 09:00 UTC (12:00 МСК)**. Время в приложении всегда реальное
(настройку времени убрали), поэтому сроки считаются от текущего момента. Номера ключевых инцидентов лежат в `_ids.json`.

## Порядок загрузки

| # | Файл | Что должно произойти |
| --- | --- | --- |
| 1 | `00_history.json` | 38 инцидентов за прошлый месяц, почти все закрыты. Цепочка из 5 «Диск заполнен на сервере расчётов» (сервис «Биллинг Абонентов», решения «Перезагрузил сервер» / «Само устранилось»). 5 решённых «Отказы при оплате картой» одной командой «Платёжные сервисы». |
| 2 | `01_now.json` | 60 текущих инцидентов. История пропадает из выгрузки (35 событий `disappeared`), 3 инцидента изменились. На доске «Фокус внимания»: в «Срочно» три новых критических (правило 1 «Новый критический»; у «Массовые отказы при оплате картой» осталось меньше 5% срока, «Не приходят SMS-коды» не взят 45 минут), в «Нужно передать» — два на координаторах, в «Срок» — те, у кого ≤ 2 ч, в «Проверить» — два «решённых за 2 минуты» и два исследования без срока. Всплывают оповещения со звуком (после первого клика по странице). Автосвязи «Один сервис за 24 часа» связывают кластер «Мой Оператор / Авторизация». |
| 3 | `02_new_critical.json` | Новый критический «Не открываются договоры: блокировки в базе» → колонка «Срочно», всплывающее окно со звуком. Окно можно закрыть, в данные это ничего не пишет. Три критических из `01` перестают быть новыми: те, что не подходят под правила 3 и 5, уходят из «Срочно» (например, «Массовые отказы при оплате картой» переходит в «Срок» с оповещением). Шаг сценария «собрать свою колонку «критический, осталось меньше 5% срока»» показывает, как вернуть такой инцидент в фокус. |
| 4 | `03_reassign_and_resolve.json` | Инцидент высокого приоритета переназначен на «КЦ ИТ Координаторы Массовых Инцидентов» → колонка «Нужно передать», оповещение. Инцидент «Отстаёт реплика СУБД» переведён в «Завершен». Инцидент «Не загружается детализация» второй раз сменил команду → «Решение буксует» (правило 7). |
| 5 | `04_reopen_again.json` | «Отстаёт реплика СУБД» снова «Назначен» — это второе переоткрытие (первое было между `00` и `01`: «Завершен» → «Назначен») → «Решение буксует» (правило 6), оповещение. «Снижение скорости у абонентов» второй раз повысил приоритет (1 → 2 → 3) → правило 8. |
| 6 | `05_complaints_growth.json` | У «Не работает подсветка сканера» (низкий приоритет) жалобы выросли с 2 до 19 (правило 11 убрано из каталога, эффект виден в истории инцидента). |
| 7 | `06_disk_full_again.json` | Новый «Диск заполнен на сервере расчётов» по тому же сервису, что цепочка из `00`. На этапе 1 он появляется как новый инцидент высокого приоритета. С подключённой моделью (этап 2) ИИ находит 5 прошлых случаев, ставит связи «Повтор» и помечает отписки в решениях. |

Повторная загрузка любого файла не создаёт ни событий, ни оповещений.

Дашборд только для просмотра: в сценарии нет отметок «Вижу», ручных связей и других действий над инцидентами. Связи на
графе создают правила автосвязей («Настройки → Автосвязи»), оповещения — колонки с включённым оповещением. Повтор
оповещения настраивается в колонке и идёт, пока инцидент остаётся в ней.

## Перегенерация

```bash
python scripts/generate_demo.py
```
