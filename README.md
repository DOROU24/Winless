# КООРАДАР

Дашборд-конструктор для координатора массовых инцидентов: доски и колонки с правилами, каталог готовых и своих правил,
история по сравнению снимков, оповещения, автосвязи и граф в стиле Obsidian.

**Дашборд только для просмотра.** Пользователь ничего не меняет в инцидентах и ничего к ним не добавляет: ни отметок,
ни статусов, ни комментариев, ни ручных связей. Данные об инцидентах берутся только из загруженных JSON и того, что из
них вычисляется. Пользователь настраивает только отображение: доски, колонки, правила, шаблоны, правила автосвязей и
общие настройки. Это проверяет тест `backend/tests/test_read_only.py`: он обходит все эндпоинты и убеждается, что
таблицы инцидентов меняет только загрузка снимка.

## Запуск

Нужны Python 3.11+ и Node.js 20.9+ (фронтенд на Next.js 16 и React 19).

**Бэкенд** (порт 8000):

```bash
cd backend
python -m venv .venv
.venv/Scripts/pip install -r requirements-dev.txt  # Linux/macOS: .venv/bin/pip; без тестов хватит requirements.txt
.venv/Scripts/python -m uvicorn app.main:app --port 8000
```

**Фронтенд** (порт 3000):

```bash
cd frontend
npm install
npm run dev
```

Откройте http://localhost:3000. При первом запуске создаётся доска «Фокус внимания». База — один файл
`backend/data.sqlite3`. Приложение загруженные данные не удаляет: чтобы начать с нуля, остановите бэкенд и удалите этот
файл. При запуске старой базы миграция сама убирает отметки «Вижу» и ручные связи из прошлых версий.

Или одной командой через Docker: `docker compose up --build`.

## Фирменный стиль

Интерфейс в цветах МТС: белые поверхности, красный `#FF0032`, графитовый текст. Цвета заданы токенами в начале
`frontend/app/globals.css`. Знак в боковой панели — заглушка `frontend/public/brand/logo.svg`: замените этот файл
официальным логотипом из брендбука МТС, путь менять не нужно. Шрифт Onest; если есть файлы фирменного шрифта MTS Sans,
положите их в `frontend/public/fonts` и поменяйте `--font` в токенах.

## Каталог правил и экран на стене

- **Каталог правил** открывается из редактора колонки («Добавить из каталога»). Своё правило можно сохранить кнопкой
  «Сохранить в каталог» — оно появится в разделе «Мои правила» и добавляется в колонки одной кнопкой. Встроенные правила
  не меняются; свои можно удалить, колонки, куда правило уже добавлено, при этом не меняются.
- **Экран на стене** (`/wall`) настраивается кнопкой-шестерёнкой слева от часов. Плитки колонок перетаскиваются
  за заголовок и растягиваются за угол (или стрелками и Shift + стрелками), их можно скрыть; задаются общий масштаб, часы и название. В плитке —
  карточки задач, список листается, клик по задаче открывает полную карточку инцидента. Раскладка хранится у каждой доски.

## Этап 2 (ИИ)

Скопируйте `.env.example` в `.env` (в корне проекта) и впишите ключ. Файл `.env` в git не попадает; его читают и бэкенд,
и `docker compose`. На сервере положите такой же `.env` рядом с `docker-compose.yml`.

| Переменная | Значение |
| --- | --- |
| `LLM_API_KEY` | ключ; без него сигналы `ai.*` помечены «недоступно», приложение работает |
| `LLM_PROVIDER` | необязательно: определяется по ключу (`sk-…` — OpenAI, `sk-ant-…` — Anthropic) |
| `LLM_MODEL` | модель, по умолчанию `gpt-4.1-mini` для OpenAI |
| `LLM_BASE_URL` | необязательно, свой адрес OpenAI-совместимого API |
| `AI_CONCURRENCY` | сколько запросов к модели слать параллельно, по умолчанию 4 |
| `AI_MAX_PER_UPLOAD` | сколько инцидентов одной загрузки отдавать модели, по умолчанию 300 |

Как работает: загрузка JSON сохраняется сразу, а анализ ИИ идёт в фоне — новые и изменённые инциденты, плюс те, по
которым анализа ещё не было или он упал. В верхней панели видно «ИИ анализирует: N из M», поля `ai.*` и связи «ИИ»
появляются по мере ответов. Повторно модель не вызывается, пока текст инцидента не изменился. Сбои сети, 429 и 5xx
повторяются до 4 раз; неверный ключ и закончившиеся средства на балансе показываются понятной ошибкой.

Сигналы ИИ для колонок: повторы и дубли, отписка в решении, подсказка команды, **волна сбоя** (активные инциденты
одной проблемы, объединённые по цепочке; в колонке с «Схлопывать волну» — одна карточка с раскрытием), **приоритет
занижен** (оценка приоритета по масштабу из текста выше текущего) и **риск просрочки** (похожие случаи решались дольше,
чем осталось до срока; считается на лету). Проверочные файлы — в `demo_data/ai_check`.

На демо-данных с `gpt-4.1-mini`: 97 инцидентов за ~3 минуты без ошибок; новый «диск заполнен» получает
`ai.similarPastCount = 5` и связи «Повтор» с цепочкой из `00_history.json`, решения цепочки помечены `ai.weakSolution`.

### Помощник координатора

Кнопка «Помощник» в верхней панели открывает диалог. Модель сама вызывает инструменты чтения
(`backend/app/assistant.py`), инструкция для неё лежит в `backend/app/assistant_prompt.txt`.

- **Колонка из фразы:** «Создай колонку с инцидентами, которые переоткрывали два раза и больше и ещё не закрыты».
  Помощник собирает правило, движок проверяет его и считает предпросмотр, а в чате появляется карточка с кнопками
  «Применить / Изменить / Отмена». Так же работают «поменяй порог», «включи звук», «отсортируй по оставшемуся
  времени» и «сделай доску для массовых сбоев»: на расплывчатые просьбы помощник отвечает с перечнем допущений.
  Поля этапа 2 без анализа ИИ не используются.
- **Вопросы по истории:** «через какие команды чаще переназначаются», «что изменилось с прошлой загрузки», «почему
  INC-… на доске», «почему постоянно проблемы с авторизацией». Ответ строится так: вывод, цифры, основания (номера
  инцидентов), «факт / предположение», ограничения данных. В конце помощник предлагает колонку для постоянного
  наблюдения.
- **«Кому отдать INC-…?»** (есть и кнопка в карточке инцидента). По каждой команде показывается: сколько похожих
  решённых инцидентов, медиана времени решения похожих (если похожих меньше минимума, по умолчанию 3, — «мало данных»;
  минимум задаётся в настройках) и сколько активных инцидентов сейчас и с какими приоритетами. Плюс подсказка ИИ и
  ограничения. Только совет: никого не назначает, сотрудников не называет.

Сам помощник ничего не меняет. Применить можно только настройки отображения (колонки и доски), и только кнопкой
человека; данные инцидентов и ITSM он не трогает.

## Устройство

```text
backend/app/
  main.py       роуты FastAPI
  db.py         SQLite и модели
  ingest.py     загрузка снимка, нормализация, сравнение, журнал событий
  fields.py     реестр полей: JSON, calc.*, hist.*, ai.* (полей, которые ставит пользователь, нет)
  rules.py      движок правил: validate / match / explain / preview
  boards.py     доски, колонки, раскладка
  alerts.py     оповещения (только для чтения, повтор пока инцидент в колонке)
  links.py      автосвязи (связи создают только правила и, на этапе 2, ИИ)
  templates.py  шаблоны досок, каталог правил, значения по умолчанию
  llm/          адаптер модели и конвейер сигналов ИИ
frontend/       Next.js (App Router): доска, карточка, конструктор с каталогом правил, граф, настройки, стена
demo_data/      демо-снимки
scripts/        генератор демо-данных
```

Бизнес-логика не зашита в код: колонки, правила, пороги, сортировка, лимиты, уровни и оповещения хранятся в базе.
Значения по умолчанию задают шаблоны в `templates.py`. Открытые вопросы — в `QUESTIONS.md`.
