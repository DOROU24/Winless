# Вопросы и принятые решения

Места, где задание допускает несколько трактовок. В коде выбран вариант, указанный ниже; его легко поменять.

## Главный принцип: дашборд только для просмотра

Пользователь ничего не меняет в инцидентах и ничего к ним не добавляет. Данные об инцидентах берутся только из
загруженных файлов и того, что из них вычисляется. Пользователь меняет только настройки отображения.

### Проверено и оставлено (не нарушает принцип)

- **Оповещения (`alerts`, `alert_membership`).** Создаются системой, когда инцидент по правилам колонки попал в колонку
  с оповещением. Это производные данные от JSON и настроек отображения, пользователь их не создаёт и не меняет.
  `GET /api/alerts/due` обновляет только служебные поля показа (`fired_count`, `last_fired_at`).
- **Автосвязи (`links.source = 'auto'`).** Пересчитываются из JSON по правилам автосвязей при загрузке снимка и при
  изменении правил автосвязей (`POST / PATCH / DELETE /api/link-rules`).
- **Связи и сигналы ИИ (этап 2, `links.source = 'ai'`, `ai_results`).** Вычисляются моделью из текстов JSON при
  загрузке снимка, пользователь их не создаёт. Вопрос: оставляем ИИ третьим источником связей, как в разделе 18 ТЗ?
- **Свернуть / развернуть колонку, порядок колонок, режим доски, «скрывать пропавшие».** Настройки отображения.
- **Таблица команд в настройках (этап 2).** Настройка подсказки, к инцидентам не привязана.
- **Закрытие всплывающего окна оповещения.** Только убирает окно с экрана, в базу ничего не пишет.
- **Поиск `GET /api/incidents?search=`.** Только чтобы найти и открыть инцидент на просмотр.

### Сохранённые правила с удалёнными полями

Если в сохранённой колонке осталось условие с `user.acked` (или другим полем `user.*`), валидация помечает его ошибкой
«Поле «user.acked» удалено: дашборд только для просмотра…». Колонка показывается с предупреждением, остальные условия
правила продолжают работать, приложение не падает. В шаблонах и каталоге таких полей нет. Колонки старой доски
«Фокус внимания» можно пересобрать: «Настройки → Сброс → Собрать текущую доску из шаблона».

## Остальные решения

1. **Пропавшие из выгрузки инциденты на доске.** Задание требует хранить их для истории, но шаблонные правила
   (например, «Исследование ситуации» или «Решён подозрительно быстро») иначе показывали бы их вечно.
   Решение: у доски есть настройка «Скрывать инциденты, которых нет в последней загрузке» (по умолчанию включена).
   Это настройка в базе, а не константа. Вопрос: нужно ли показывать пропавшие по умолчанию?

2. **Перетаскивание карточек.** Карточки попадают в колонки по правилам, а ручное закрепление карточки было бы
   данными об инциденте не из JSON. Поэтому перетаскиваются только колонки (`@dnd-kit`).

3. **«Новый» инцидент** = впервые появился в последней загрузке (`first_snapshot_id = последний снимок`). При повторной
   загрузке того же файла инцидент перестаёт быть «новым», потому что в последнем снимке он уже не появился впервые.

4. **Повтор оповещения** = каждые N минут, пока инцидент остаётся в колонке. Время всегда реальное: настройку
   виртуального «сейчас» убрали (для автотестов есть только переменная окружения MTS_NOW). Если инцидент
   впервые попал в другую колонку с оповещением, создаётся новое оповещение.

5. **`hist.delta`** берёт изменение только между двумя последними снимками. Если инцидент появился в последнем снимке,
   значение пустое.

6. **Демо-сценарий «переоткрыли дважды»** уложен в файлы `00 → 01` (первое переоткрытие) и `03 → 04` (второе), потому
   что переход «Завершен → Назначен» нельзя показать дважды в одном снимке. Подробности — в `demo_data/README.md`.

7. **Колонка «Повторы и дубли»** в шаблоне «Фокус внимания» создаётся только когда подключена языковая модель
   (`LLM_API_KEY`). Без модели правила 11–15 видны в каталоге с пометкой «нет данных».

8. **Файл ТЗ.** Обновлённое ТЗ к сообщению не приложилось: в `Downloads/coordinator_dashboard_agent_spec.md` осталась
   версия с «Вижу» и ручными связями. Переработка сделана по пунктам сообщения с принципом «только просмотр».

9. **Отметка «прочитано» у уведомлений** (`alerts.read_at`, `POST /api/alerts/read`) — осознанное исключение из
   «только просмотр»: это состояние самого уведомления, а не инцидента. Таблицы инцидентов и связи по-прежнему меняет
   только загрузка снимка, это проверяет тест. Отметка общая для всех, кто открывает пульт: прочитал один координатор —
   уведомление прочитано у всех. Нужна ли отдельная отметка для каждого координатора — вопрос заказчику. Уведомления,
   созданные до появления отметки, при миграции считаются прочитанными.
